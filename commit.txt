[2026-11-03] - Ajout du statut professionnel et prefixation [TEST] des tickets Oline en dev

What changed:
- Creation de l'enumeration StatutProfessionnel (employe, prestataire, stagiaire) :
  * Modele User : ajout de la colonne 'statut_pro' (nullable pour declencher automatiquement la finalisation sur les profils existants).
  * Modele FluxRequest : ajout de la colonne figee 'dem_statut_pro' (instantané a la soumission de la demande).
- Schema et controle d'acces Pydantic :
  * 'UserOut.profil_incomplet' evalue a True si 'statut_pro' est manquant, forcant l'ouverture automatique du modal des la connexion.
  * 'ProfileUpdateIn' impose la selection du statut professionnel valide (employe, prestataire, stagiaire).
  * 'RequestDetail', 'RequestSummary', 'PublicVerifyOut' et 'UserAdminOut' exposent le statut du demandeur.
- Sceau cryptographique et tracabilite :
  * 'seal.py' integre 'dem_statut_pro' dans le tuple canonique SHA-256 de calcul de l'empreinte ('content_hash').
  * 'pdf.py' affiche le statut professionnel du demandeur sur le document PDF officiel.
- Integration Oline / iTop et differenciation DEV / PROD :
  * Lorsque l'environnement est hors production ('ENVIRONMENT != "prod"', par exemple 'ENVIRONMENT=dev') :
    - Le titre du ticket Oline est automatiquement prefixe par '[TEST][Flux] ...'.
    - Un avertissement explicite est insere en debut de description pour empecher tout deploiement accidentel par l'equipe reseau.
  * En environnement de production ('ENVIRONMENT=prod') :
    - Le titre officiel sans prefixe de test '[Flux] ...' est conserve.
  * Mention nominative et statut professionnel du demandeur inclus dans la description du ticket Oline.
- Migration idempotente :
  * Ajout de 'migrate_schema' dans 'app/database.py' (ALTER TABLE ADD COLUMN IF NOT EXISTS pour SQLite et PostgreSQL) execute au demarrage FastAPI (lifespan) et dans le seed.
- Interface React :
  * 'ProfileModal' : ajout d'une liste deroulante obligatoire pour choisir son statut professionnel.
  * 'UserMenu' : affichage du statut professionnel dans l'en-tete utilisateur.
  * 'NewRequest' : recapitulatif du statut professionnel dans le bloc demandeur.
  * 'RequestView' : badge du statut du demandeur dans la vue detaillee de la demande.
  * 'admin/Users' : colonne et affichage du statut professionnel dans le tableau des comptes.
- Docker et compilation :
  * 'frontend/Dockerfile' : passage de l'etape builder a 'node:20-slim@sha256:2cf067cfed83d5ea958367df9f966191a942351a2df77d6f0193e162b5febfc0' pour resoudre la dependance glibc de Vite/lightningcss lors du build en conteneur.
- Tests :
  * Ajout de 'tests/test_statut_professionnel.py' validant le blocage de profil incomplet, la mise a jour de profil, le figeage sur la demande et le formatage Oline.
  * Mise a jour de 'tests/test_oline_integration.py'.
  * Suite complete : 38/38 tests valides.
